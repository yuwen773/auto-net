# 自动认证恢复与单页设置实施方案（讨论稿）

日期：2026-10-27。此文为目标设计。截至 2026-11-01，工单 #28–#41 的离线实现已落在 `codex/ui-avalonia`（决定见 ADR-0011 至 ADR-0021），但**尚未发布，也未在真实门户、真实断网或真实 UAC 下验收**；本机已安装程序可能仍是旧版。下文保留为目标行为；凡与当前运行行为不一致处，以 ADR 和 `docs/VALIDATION.md` 为准。

## 已确认的目标

- 以自动恢复为优先。普通协议与内嵌认证通道共用实际可能发出的凭据提交额度；首次提交后，结果持续未知时最多额外提交两次，实际提交之间至少间隔 120 秒。
- 外网恢复时暂停提交并继续只读复检；外网可用不证明门户接受了凭据。额度仅在门户明确确认认证成功或用户主动确认重新开始认证后重置；重启、外网暂时恢复和保存设置都不重置。
- 页面来源或提交目标无法确认可信时，不向页面自动填入凭据。用户说明本校当前页面上的验证码为展示项，无需填写；不新增识别或等待验证码的流程。
- 主窗口左侧设置页直接编辑，保存时请求管理员确认；保留密码留空规则、DPAPI、受限 ACL 和认证安全状态。
- 主窗口提供可视化认证页，允许查看学校门户并处理必要的页面交互，同时保留后台自动认证；用户离开该页不能误触发第二次认证。
- 不熟悉的功能先对比开源实现；版本、许可和证据见[调研记录](../research/2026-10-27-auth-recovery-sources.md)。不直接复制 CampusConnect 当前版本代码；若考虑引入，另行核对具体版本与许可。

## 与现状和既有决定的关系

[ADR-0001](../adr/0001-submission-recheck-resolution.md) 与 [CONTEXT.md](../../CONTEXT.md) 当前记载“未知结果不自动重发”；本设计经用户选择后允许受限重试，修订决定已写入 [ADR-0011](../adr/0011-bounded-submission-retry.md)，实施时同步实际行为文档。ADR-0009 的复核链与安全状态承诺保持；实现要补齐内嵌通道。ADR-0007 的普通托盘与管理员操作分离仍保留。尚未交付时，不覆盖历史 ADR 或声称当前已具有新行为。

用户新增要求在主窗口内部展示网页，因此需重新评估 ADR-0009 放弃在 Avalonia 内嵌网页的界面形态；独立 WebView2 进程与权限分离的安全目的仍须满足。**主窗口承载已由隔离原型验证可行**：Avalonia 12.1.4 主窗口经 `NativeControlHost` 承载 WebView2，原生父子关系经 `GetAncestor` 校验；证据与盲区见[原型证据](../research/2026-10-27-visual-auth-prototype-evidence.md)。原型只排除了架构风险，不等于已有生产实现。

现有 AuthenticationBlock.Attempts 也计入预检，RetryCoolingDown 限制为 2–60 秒；不能直接把它解释成 120 秒的凭据提交额度。既有自动降级规则在预检尝试用尽时可能产生通道授予，因此应分开维护预检计数和可能发出凭据的提交计数，而不是叠加两个独立的三次额度。

## 凭据提交与恢复

### 同一故障中的状态

以下是行为模型，具体持久字段和接口在实施设计中落实：

1. **待检查**：只读检查目标 Wi-Fi、恢复开关、外网与门户。外网可达则暂停提交，但继续按受控节奏只读复检；门户明确登录时经审计解除未知状态并重置额度。
2. **准备提交**：确认目标网络、可信门户、恢复开关与设置仍适用；两种载体经同一安全状态和跨进程串行化机制复核。区分页面/协议预检次数与提交次数。
3. **提交已预留**：在可能发出凭据之前，持久记录此尝试、共享额度、与最早下次提交时刻相关的证据；完成持久写入和最终复核后才允许提交。写入失败、锁竞争或状态变化时不提交。
4. **执行中**：协议请求或内嵌会话最多一个。辅助进程仍在操作、显示等待人工操作或其是否结束无法确认时，不允许另一条路径发送凭据；不得让服务的现有 2/6 秒复检提前释放该状态。
5. **结果明确**：可信门户证实登录成功时写解除审计、按修订比较解除并重置额度；明确密码错误、绑定拒绝等不适合重试的失败时停止提交并提示。可确认未登录时仍遵守共享额度和最短间隔。
6. **结果未知**：持续只读复检；如果外网不可达、前次会话已结束或已确认失联、来源和目标仍可信、恢复仍开启，且间隔与额度满足，重新复核后可再提交。每次重新提交都消耗共享额度。
7. **额度耗尽**：停止自动提交，继续低频只读复检；若后来门户明确成功则自动消解。用户可以明确确认“重新开始认证”，先审计并重新核对状态，再重置额度；该操作不因保存设置或重启而发生。人工浏览器中的自主操作无法由程序限制，也不声称可计数。

120 秒是相邻可能发出凭据的最小间隔，并非两次预检之间的间隔。计时证据必须覆盖执行中、突然退出和结果未返回；无法可靠确认上次提交时刻时，应保守延后，而不是缩短等待。墙钟回拨、时间不可信、跨重启以及持久化失败必须有明确的保守处理并以测试验证。

### 跨进程、重启与升级

- 把协议与内嵌载体接到同一受保护的授权与结果状态；托盘授予只是启动意图，不能取代提交授权。提交前预留必须受跨进程锁、修订比较和原子持久化保护。
- 区分“已预留但尚未能证明发送”“可能已经发送”和“明确结束”。无法区分时按可能发送处理并计入额度，不能为了恢复速度伪造未发送。
- 认证通道进程存活、失联、会话结束及用户交互应有可验证的生命周期。不能仅凭用户目录的结果文件或自报时间释放机器级阻断；结果关联、权限和对端身份必须经过验证。只读门户证据与已保存状态关联后，才允许受审计的状态变更。
- 同一授予并发观察、托盘重启、服务重启或 UAC 拒绝，不得使授予重复触发越过共享额度。权限拒绝或启动失败需要明确反馈；不暗中绕过保护。
- 持久格式调整必须保持旧版本兼容。旧版未知状态、损坏记录、版本未知、写入失败或回滚后无法安全解释时保守保留阻断和证据，不能因为迁移丢失旧记录而自动获得新额度；单独测试升级与回滚。

### 网页与结果

- 参考 [CampusConnect 的无凭据表单探测与导航代次](https://github.com/Ye9137/CampusConnect/blob/7761c20eb63245da796cbbcf92b859dd74f1cf97/Windows/source/PortalController.cs#L367-L394)，以及其成功、明确拒绝和未知结果的区分；适配本校的可信页面证据后再使用。
- 参照 [微软 WebView2 安全指导](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/security)，检查实际来源、导航与框架，并在填入凭据前再次核对；验证 HTTPS、允许的来源及提交目标。不能以 URL 路径变化单独认定成功，不能将跨主机跳转自动视为可信。
- 隔离原型发现：仅在 NavigationStarting 取消导航时，本地监听仍收到 HTTP GET；该现象与 [WebView2 公开问题](https://github.com/MicrosoftEdge/WebView2Feedback/issues/4765)一致。原型增加 WebResourceRequested 后，在主页面及沙箱框架的本地测试中未收到 HTTP 数据，但仍观察到 TCP 连接；不能将其视为完全网络隔离。正式实现须验证所有相关请求来源、重定向、提交与新窗口，不能只依赖取消导航或未经验证的过滤覆盖。
- 隔离原型还发现 **WebSocket 绕过资源过滤**：`WebResourceRequested` 对 ws/wss 不生效，`Network.setBlockedURLs` 同样无效（与 [WebView2 公开问题](https://github.com/MicrosoftEdge/WebView2Feedback/issues/4303)相符）。原型的应对是只作用于该 WebView 的本地允许列表代理，代理侧用 `IP_UNICAST_IF` 加源地址绑定把出站连接钉到目标网卡；原型验证了 WebView2 确实服从 `--proxy-server`，且代理拒绝的请求一次都没直连目标。**WebRTC/STUN 的走向未查清，不能声称已被拦截。** 正式实现必须自带这些回归，且不得保留原型中把域名映射到本地地址的测试用口子。
- 页面、框架、来源和提交目标发生变化时取消旧页面的填表意图。必要的可信来源与学校实际流程通过离线夹具和获授权的现场只读证据确认；不要为追求自动化而接受任意门户跳转。
- WebView2 尽量运行在普通用户权限；与受保护授权和凭据操作分离。凭据在进程间如何交接需要单独设计和验证，不能把用户可写的回执当成安全授权。
- ManualOnly、Automatic、Off 的用户选择及 UAC 行为须保留；自动重试不应偷偷把手动模式变成自动模式。确有必要的人工交互时不进行并发提交。

## 主窗口可视化认证页

- 左侧增加“上网认证”入口，在主窗口内容区显示学校门户页面以及网络与认证状态，支持用户查看和必要时操作页面；状态变化需要清楚区分联网、认证成功、结果未知与等待重试。
- 后台协议认证保持自动运行；查看认证页不是提交意图，不因页面打开、关闭或切换而自动增加一次凭据提交。不凭另开窗口来代替用户要求的主窗口内页面。
- 后台确需使用内嵌通道时，页面展示同一认证会话及其状态；不能因为打开页面而另起一次会发送密码的会话。若后台走协议认证，认证页展示当前状态；网页如何附着或载入不得触发额外提交。
- 当前主窗口会随状态更新重建页面内容；浏览器宿主需要独立管理生命周期，不能因此丢失已填写内容，也不能在普通状态刷新时重新导航或提交。后台协议认证不经过浏览器，认证页不能声称展示了当时的网页操作。
- 被动浏览、程序自动填写、程序自动提交和用户在门户页面的自主操作应清晰区分；程序控制的提交统一经过共享额度与授权。对任意学校页面的脚本及用户直接点击，不能预先假定一定可以完整拦截或计数，必须先用真实类型的离线夹具验证并说明边界。
- 用户已确认“先查看”：进入页面不额外填写或提交密码，后台自动认证继续运行。程序不能默认把持久权限、已保存密码或门户 cookie 交给不可信页面；显示页面不以降低现有凭据与页面来源保护为代价。

- 校验 Windows 会话与 UAC 对跨进程窗口嵌入的影响、WebView2 Runtime 缺失的受控提示及用户会话退出后服务行为。用隔离网页与虚构凭据验证；现场门户兼容和自动恢复仍需单独授权与验证。

### 自动认证操作动画

- 用户已确认：内嵌浏览器自动认证时，在可视化认证页显示模拟智能体操作页面的虚拟鼠标，让填写、勾选和提交过程直观可见；不移动或接管 Windows 真实鼠标指针。
- 动画应以实际认证动作或明确的步骤状态为依据；动作失败、跳过、页面不可见、目标位置不可用时如实呈现，不能虚构点击、成功或回放不存在的历史操作。普通协议后台认证没有网页动作，不播放网页填写动画。
- 动画只做视觉呈现，不触发凭据提交、不改变共享次数、120 秒规则和状态机。应不阻挡用户操作，不延迟后台自动恢复，不显示或记录密码、账号、Cookie 及页面敏感内容；对截图、事件和日志做脱敏验证。
- 如果需要模拟指向页面控件，须验证 WebView2 与 Avalonia 的窗口层级、焦点、滚动、缩放、DPI、框架与目标位置变化。原型已覆盖原生父子关系、虚拟指针不移动系统鼠标、150% 浏览器缩放下的滚动定位与隐藏/重现；**未覆盖**系统多 DPI、键盘焦点、无障碍与目标位置在滚动/尺寸变化后的失效检测。目标位置或事件不可可靠取得时，降级为准确的步骤提示而不是假装已点击。
- 用户切页或隐藏窗口时，认证继续且不必为了动画再打开网页或重放动作；尊重 Windows 减少动画设置，无法安全显示时使用静态状态。
- 用户已确认：手动操作认证网页时暂停新的自动填表和提交，后台网络检查继续运行；已经发出的凭据请求不能撤销，继续按结果未知、复检和共享额度规则处理。页面清楚呈现“正在手动操作”，虚拟指针不与用户操作争抢。
- 用户停止操作约 15 秒后自动重新检查：再次核对网络、认证状态、页面来源、表单、前次提交是否结束及共享次数和冷却，满足条件后才允许恢复自动操作；若用户再次操作则重新等待。禁止覆盖已输入的内容，不能把 15 秒空闲本身解释成提交授权或认证成功。
- 现有展示性验证码不需要输入；如果未来页面确实要求其他人工交互，不能因短暂没有输入就猜测该交互已经完成，也不能由虚拟鼠标代替用户决定。页面变化、用户手动提交或不能可靠检测交互时，应以实际可证实状态协调，避免重复提交或覆盖用户输入。
- 页面可见时，虚拟指针及步骤提示只订阅当前会话的受控事件；开始填写、控件确认、发起提交、等待结果及失败/中止分别表达，不从 URL 或动作动画推断成功。步骤发生时页面未显示、事件丢失或控件坐标过期，就显示当前可证实状态，不补演过去的鼠标轨迹。
- 动画覆盖层不得截获真实鼠标或键盘；目标位置发生导航、滚动、窗口尺寸或 DPI 变化时清除过期指示并重新校验。自动操作结果仍以真实页面与认证状态机为准，虚拟指针本身不调用页面或系统鼠标操作。
- 隔离验证事件与真实动作的对应、目标找不到/页面跳转、后台完成后打开页面、真实鼠标不移动、人工操作可达、遮挡与密码保护、禁用动画/减少动画、滚动与 DPI，以及后台认证速度不因展示而改变。
- 用包含同源及受限框架、焦点变化、普通输入、用户自行提交和页面跳转的离线夹具验证手动与自动操作协调；交互检测的盲区应明确披露，不能声称能记录或控制浏览器中所有人工提交。
- 窗口隐藏或切页不能被当作用户提交完成；重新展示时只呈现当前会话的可证实状态，不主动导航或提交。关闭主窗口与退出托盘按实际生命周期分别验证：协议后台服务不依赖主窗口；需要用户会话的 WebView2 不能在用户会话退出后保证继续运行，必须保留未知状态和额度，待可用会话恢复后再按规则检查。
- 现有内嵌通道启动可能出现 UAC；新方案须在权限隔离下验证用户会话可用时如何保持后台自动认证，不得预先声称无需 UAC 或让后台服务直接运行 WebView2。不可用、失联及权限失败时明确提示并保留状态。**跨管理员账户 UAC 本机无法构造**（内置管理员已禁用、当前账户为 Medium 拆分令牌），该场景只能在有条件的环境验证；原型只覆盖了同账户内的 SID/PID/ACL 核验。

## 主窗口设置页

- 把现有独立窗口的校园 Wi-Fi、账号、新密码、代理/UU 检测、恢复开关、电源选项和通道模式放入左侧设置页；外观主题继续在同一页。按实际现有字段和校验规则迁移，不因合并变更业务选项。
- 密码输入始终遮挡；不显示或回读已保存密码。同一账号留空保留旧密码，首次设置或修改账号必须输入新密码。保留校验、Wi-Fi 配置选择、暂停标记和失败反馈。
- 点击保存时请求 UAC；取消或拒绝授权不得写入。主窗口不整体提权。已输入密码可能短暂存在普通 UI 进程内存，操作结束尽量缩短其保留时间。
- 仅传递保存所需的信息；禁止密码出现在命令行、环境变量、日志和明文临时文件。对跨进程通信设计最小授权、双方身份核验、一次性关联、超时和防重放；[命名管道默认 ACL](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights)不能直接作为凭据保护依据。
- 普通用户与提权用户可能是不同账户，必须验证跨账户 UAC、正确的权限与会话隔离；不可假设同一用户管道一定适用。保存后回显受控结果，刷新非秘密投影；失败应如实报告已发生的写入，避免宣称整个保存具有尚未实现的原子性。
- **这条跨进程交接是本设计的真实需求，不是可选门槛**：设置页搬进非提权主窗口后，密码必然先在普通 UI 进程里存在，再交给提权进程落盘。现有实现之所以"密码不跨进程"，只是因为设置窗口目前整个跑在提权进程内（`ElevatedSettings.Production()` 在提权进程里开窗）；一旦按本设计合并设置页，这条捷径就不存在了。原型已在**同账户**内验证显式 ACL + 对端 SID/PID 核验可行（伪造对端时服务端拒绝、客户端中止发送），但**跨管理员账户在本机无法构造**（内置 `Administrator` 已禁用，当前账户是 Medium 拆分令牌），只能留待有条件的环境验证；跨完整性级别握手、恶意同用户进程、进程注入与路径替换同样未验证。

## 实施顺序与验收

1. **离线基线和安全状态设计**：保护现有工作区，固定当前提交与未提交变更；梳理旧状态、可用锁与恢复流程。以隔离临时目录和假时钟验证状态迁移、授权前持久预留、写失败拒发及旧数据保守处理。
2. **共享提交规则**：先用假门户和虚构凭据建立协议与内嵌载体共享计数的行为测试，再接入同一状态机。验证 0/1/2 次额外提交、120 秒边界、时钟变化、同时竞争、掉电窗口、重启、在线暂停和明确失败停止。
3. **内嵌通道收口**：引入受保护的跨进程授权/结果生命周期，参考现有网页识别思路；本地虚构页面覆盖可信、跳转、外站、框架、错误页、页面变化、提交后丢结果、会话仍活动、UAC 拒绝、进程失联和伪造回执。
4. **可视化认证页**：主窗口承载的技术原型已完成（见[原型证据](../research/2026-10-27-visual-auth-prototype-evidence.md)），本阶段直接做正式页面并接入共享认证状态和会话，覆盖仅查看不提交、后台进行中打开页面、手动输入、切页、最小化及退出、DPI、Runtime 缺失与外站跳转。原型未覆盖的项（真实 TLS/重定向/新窗口/Service Worker、系统多 DPI、无障碍、用户会话退出）作为本阶段回归交付，而不是再开一轮原型。
5. **设置页合并**：复用现有设置验证与保存规则；隔离测试普通用户、取消/拒绝 UAC、不同账户提权、并发保存、密码不外泄、密码留空及更改账号。真实 Windows 窗口验证键盘、布局、缩放与 UAC；截图不包含真实账号或密码。
6. **交付检查**：构建和相关回归、安装/升级/回滚契约、日志脱敏及文档；真实学校门户和真实断网恢复须单独授权并现场验证，不以离线测试代替。测试结果、现场限制和未解决事项明确记录。
