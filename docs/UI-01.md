## 1. 信息架构

主窗口 `src/AutoNet.Tray/MainForm.cs` 分为六区，自上而下：

| 区 | 内容 | 依据 |
|---|---|---|
| ① 品牌 + 服务状态 | 名称、后台服务运行状态、最近检测时间 | `StatusSnapshot` 是否可读及其新鲜度 |
| ② 主网络状态 | 状态图标 + 标题 + 一句解释 + 下一步 + 技术细节 + 附加状态条 | `NetworkDisplay` |
| ③ 自动恢复与主动断线额度 | 已用/总额、未确认断线、下次允许重试、恢复条件 | `StatusSnapshot` 的额度字段 |
| ④ 网络诊断 | 校园 Wi-Fi / 校园网认证 / 校园网直连 / 代理与系统路径 / UU 远程 | 快照原值，不加工 |
| ⑤ 最近一次恢复记录 | 时间 + 观测耗时 + 来源不可确认的说明 | 快照原值 + 固定免责文案 |
| ⑥ 操作区 | 设置… / 暂停自动恢复 / 查看日志 / 安装服务… / 解除认证暂停… | 现有命令，语义未变 |

分区之间不合并状态。**联网与否**由主状态单独表达，**认证是否被暂停**由附加状态表达，二者互不改写；「认证状态未知」与「认证失败」是不同主状态；「检测到联网恢复」与「AutoNet 自动恢复成功」在文案上刻意区分——第 ⑤ 区固定写明「只说明 AutoNet 观察到外网重新可达，无法区分是程序自动恢复、人工处理还是网络自行恢复」。

主动断线默认开启，额度、已用量、下次允许重试与恢复条件都直接显示，不隐藏。

## 2. 状态映射（`src/AutoNet.Core/NetworkDisplay.cs`）

纯函数，不引用 WinForms 类型，因此可以在离线测试里穷举。`NetworkDisplayMap.Map(StatusSnapshot?, TimeSpan? age)` 返回 `NetworkDisplay(Primary, Additional, Title, Explanation, NextStep, TechnicalDetail)`。

15 个主状态、6 个附加标志。关键规则：

- 未知的服务状态字符串 → `Unrecognized`，标题「未识别的服务状态」，`IsHealthy == false`。**永不崩溃，永不显示为在线**。
- 快照缺失或超过 15 秒未更新 → 独立标题「后台服务未就绪」/「后台状态已过期」，同样不是健康态。
- `Direct == "外网可达"` 只表示校园路径通过了内容检查，附加标志 `EgressUnverified`（「物理出口未核验」）始终同时出现。
- `需要处理认证` 的文案跟随 `CredentialsBlocked` 而非状态字符串：未被阻断时不能说「凭据提交已暂停」。有回归测试锁住。
- `TechnicalDetail` 只从受控字段拼装（阶段 / 失败分类 / HTTP 状态 / 持久状态 / 是否已发起凭据请求），**不含 `Detail`、不含 `LastError`、不含任何异常原文或 URL**。

## 3. 视觉规范（`src/AutoNet.Tray/Theme.cs`）

字体 `Microsoft YaHei UI`。品牌色 `#124882`，窗口底 `#F7F9FC`，卡片白。间距：页边距 24、卡片内边距 16、卡片间距 12；按钮高 34；图标 32；圆角 8。

状态配色 `Theme.Palette(NetworkPrimaryState)` →（前景色，表面色），五档语义色：健康 / 警告 / 问题 / 注意 / 中性。**颜色永远不是唯一载体**——每个状态同时有图标、标题文字和解释文字。

可复用组件 `Ui.Card()` / `CardFill()` / `Stack()` / `Text()` / `Button()`，以及 `Ui.Wrapping<T>()` 扩展：让可换行标签在任何宽度下都留在其容器内，随 `SizeChanged` 重算。这样 DPI 适配来自布局本身，不需要按缩放比维护一张尺寸表。

状态图标 `src/AutoNet.Tray/StatusIcon.cs` 用 GDI+ 现画并按 (状态, 尺寸) 缓存，不随定时刷新持续增加。应用品牌图使用用户提供的 `assets/AutoNet.png` 及配套多尺寸 `AutoNet.ico`，由 `NetworkIcon` 读取嵌入资源，覆盖主窗口 Logo、窗口图标和系统托盘；Service/Tray 的 EXE 图标使用同一 ICO。

## 4. 日志中心（`src/AutoNet.Tray/LogForm.cs`）

- 按日期切换，最新在前。
- 四个分类筛选：全部事件 / 状态变化 / 恢复动作 / 认证相关。
- 左侧时间线列表，右侧技术诊断详情，详情末尾固定声明「物理出口、UU 会话与真实认证仍待现场验收」。
- 读取只取文件尾部（`LogTailReader`），窗口上限 4 MB、单日最多 300 条。处理 BOM、CRLF、UTF-8 多字节被切断、末行写了一半。损坏行跳过而非整批失败。
- 快速切换日期用 generation token 做 last-write-wins，落败的读取不碰任何控件；`disposed` 后不再触碰控件。
- **「复制脱敏摘要」由 `LogSummary.Format` 从白名单字段重建**，不是复制渲染文本，也不对全文做正则替换。`Detail`、`LastError`、`Uu`、`SystemPath` 永远不进入摘要；未知枚举值折叠为「其他事件」/「未知」。复制后附带说明行，写明异常原文、账号与网络标识未包含。

### 与冻结决策的一处偏离（Q10）

原决定用 `ListView.VirtualMode`。实际实现保留普通 `ListView`，读取上限为 300 条，并兼容现有 `DrawToBitmap` 截图流程。更正此前说明：.NET 提供受支持的 `VirtualListSize` 属性，不能以“没有受支持的项数接口”作为偏离理由。虚拟列表的截图兼容问题是此前记录的观察，本轮没有重新验证；普通列表也不据此宣称读屏体验更优。

## 7. Q11b：`LastError` 写入路径审计（决定 C）

结论：**未发现泄露，不需要单列安全阻断。**

`StatusSnapshot.LastError` 由 `RecoveryJournal.LastError` 生成，等于各 `Fault()` 条目的拼接，而 `Fault(scope, summary, error)` 产出的是 `summary + "：" + error.GetType().Name` —— 异常在这段展示摘要中**只贡献类型名**，不含消息、不含 URL。当前 `MonitorWorker` 的 18 处调用点里 17 处的 `summary` 是字符串字面量；唯一的一处传入 `detail`，紧邻的赋值来自 `lastAuthentication.SafeSummary`，是允许展示的受控分类串。结构化诊断日志另有受控错误码和调用位置，不属于这段 `LastError` 摘要。

界面层本来就不渲染 `LastError`：`NetworkDisplay.Technical()` 与 `LogSummary.Format` 都把它列入不可输出集合。
