## 测试边界

通过公开行为验证认证请求、设置校验、恢复策略以及后台监测故障恢复。外部 HTTP、时钟、文件和 Windows 网络/API 使用离线替身或独立临时目录；不读取本机真实凭据，不访问学校认证服务器。不测试私有方法。

## 交付门槛

1. **工程加固完成**：安全守卫、状态处理、离线回归、构建、审查通过。安装脚本的语法检查不等于安装回滚通过；CI 配置存在不等于远端 CI 已运行。
2. **实机功能通过**：指定 Wi-Fi 断连、真实认证失效、TUN 共存、未登录恢复与第二设备会话均有脱敏现场证据。
3. **性能与稳定性通过**：先确定重复次数与指标口径，报告成功率、最大值和失败原因，再判断是否达到 15 秒目标。

现场受阻时只能交付工程阶段，产品目标保持“待验收”。每项记录修改、回归、真实退出码、未验证边界和回滚办法。不得通过降低 TLS、凭据守卫或用户选网边界来满足性能指标。

## 本次风险与回滚

- 没有部署工作区程序；已安装服务和现有认证阻断保持原状。历史故障及本次只读证据见 [PORTAL_DIAGNOSIS_20261010.md](PORTAL_DIAGNOSIS_20261010.md)。
- 配置/DPAPI/阻断文件格式保持兼容；旧合法的学校 HTTPS 443 根地址仍可用，其他地址明确拒绝，不静默迁移到新目标。
- 认证先校验全部前置条件；缺字段、异常结构、重定向和 TLS 错误不会绕过守卫。诊断类不接收凭据。没有新增高校或远程云依赖。
- 不响应取消的辅助任务会保持“超时/未知”并等待原任务结束，避免不断创建后台检测；主恢复继续。不可强杀网络库内部任务。
- 安装回退、ACL 与清除数据尚未在系统中执行；只完成源码审查和脚本解析检查，不能宣称安装权限门槛已通过。
- 回滚代码使用本轮提交的 `git revert` 后重新构建。部署后的程序回退须由本机操作者使用原发布包，保留 private 数据并按 VALIDATION.md 核验。
