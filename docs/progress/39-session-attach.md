# #39 后台会话附着与页面状态投影

2026-10-30 在 `codex/ui-avalonia` 的 `007276d`（#38 已合入）基础上实施。本工单让「上网认证」页在后台内嵌认证通道运行期间不再另起一条浏览器会话，只投影会话状态；协议认证仍只投影状态。决策记录见 [ADR-0017](../adr/0017-auth-page-session-attach.md)。

## 实现

- **会话信号**：`AuthChannelLauncher.SessionActive` 把既有忙态判定收成一处——本进程发起的辅助进程仍存活，或外部启动锁仍被持有。`Describe()` 与 `Launch()` 复用同一属性，不再各写一遍。
- **宿主核对入口**：`IAuthPageBrowserHost.Refresh()`（工单 #39）。真实宿主在会话进行中丢弃自己的浏览器与代理并投影 `ChannelSessionActive`；会话结束回到未附着，**不**自行附着。QA 假宿主与失败关闭骨架宿主为无操作。
- **真实宿主边界**：`AuthPageWebViewHost` 在附着、可见性恢复、原生表面创建与浏览器初始化等待之后都重新核对会话；会话进行中的初始化会放弃导航并丢弃浏览器；初始化失败若恰逢会话开始，只投影会话状态而不是可重试的 `Failed`。
- **协调器恢复策略**：`AuthPageCoordinator.Update` 在每个状态刷新周期先 `host.Refresh()` 再投影。宿主回到未附着时，只有**成功附着过**（`hadAttached`）的页面才恢复一次只读附着；从未打开过、或上次附着受控失败的页面都不会被自动拉起。恢复不重放页面操作、不提交凭据。`host.Refresh()` 的异常不阻断投影（保留上一次状态，下一轮再核对）。
- **文案**：`AuthPageModel.HostCopyFor` 新增 `ChannelSessionActive`——“内嵌通道会话进行中 / 本页只显示该会话的状态，不会另起会发送密码的会话”。`HostAvailable` 仍只认已附着，会话状态不提供重试入口（它不是失败）。后台说明同步：会话进行中不再落到“后台按协议认证运行”，改为陈述会话事实——授予字段可能已被消费，本地进程事实不依赖快照。
- **装配**：`App.axaml.cs` 中认证页宿主先于通道发起器创建，用延迟绑定 `() => authChannelLauncher?.SessionActive == true` 读取会话状态；通道实例创建后立即补上，不改变既有初始化顺序。
- **回归**：`AuthPageRegression` 新增 5 项——真实宿主在会话中不读网卡/不启第二个代理、受控失败后不因会话结束自动重试、未打开的页面不凭空附着、会话期间切页与最小化不改投影、会话状态与协议认证文案互不冒充（协议载体用假宿主走一次真实附着）；两个既有假宿主补上 `Refresh()`，宿主抽象反射断言新增 `Refresh`。

## 审查修复（2026-10-30，Standards + Spec）

- **受控失败后不再自动重试**：恢复条件从 `attachAttempted`（失败前就置位）改为 `hadAttached`（只有成功附着过才为真，`RuntimeMissing`/`NetworkBoundaryUnavailable`/`Failed` 会清掉它）。会话结束不会再顺手重试一次用户必须显式重试的失败；新增回归钉住。
- **初始化中途开始会话**：浏览器初始化等待期间发现会话开始，改为直接走 `EnterChannelSession()`——立即停代理并投影会话状态，不再留下一个刷新周期的陈旧 `Attached`。
- **界面线程防御**：`Update` 中的 `host.Refresh()` 用受控 catch 包住，核对失败不阻断投影，下一轮再试。
- **单一来源**：`ChannelSessionActive` 快照收成 `AuthPageHostSnapshot.ChannelSession()`；`App.axaml.cs` 的延迟绑定槽位与实际实例合并为一个变量。
- **回退无关注释/改动**：撤销测试夹具抽取（`AuthPageFixture`）与随之产生的 BOM、恢复 `AuthPageBoundaryRegression.cs` 原样；去掉 `AuthChannelLauncher` 的多余空行；删除 QA 假宿主里不可达的 `SimulateForQa` 会话分支。
- **测试稳定性**：真实宿主的恢复附着改为有界等待（最多约 2 秒），不再用固定 `Task.Delay(20)` 赌时序。
- 审查遗留并接受：AC1 的“展示同一会话”按 ADR-0017 的互斥解释（不共享通道进程的 WebView2 会话）；协议认证下页面仍加载门户页（#38 的只读展示语义）；`Refresh()` 在无会话宿主里显式空实现（默认实现会藏起契约）。

## 遗留

- 真实通道进程运行期间打开认证页、以及会话结束后页面恢复的现场行为，属 NOT_RUN，需要真实 UAC 与门户授权。
- 会话进行中丢弃展示页浏览器会丢失未提交的页面输入；展示页只读、不提交，已在 ADR-0017 记录为接受的代价。
- GitHub 在本轮实施时不可达，`#39` 的 issue 正文未回读；验收点以仓库内 `CONTEXT.md`、`docs/VALIDATION.md` 与 ADR-0015/0016 的既有表述为准。
