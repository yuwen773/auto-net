# #34 提交额度审计重置

2026-10-29 在 `codex/ui-avalonia` 的 `848e1db` 基础上实施。依赖 #32 的有限重试实现存在于本地提交 `848e1db`；其 GitHub 工单仍开放，本地结果不代表发布或实网验收。

门户提交响应明确成功与只读复检确认成功使用同一审计、认证和额度修订比较流程，审计区分两种证据。人工“重新开始认证”由独立提权入口确认，持执行锁后重验状态、写审计并重置额度，不解除认证暂停或改变主动断线额度。人工确认标记绑定新额度修订，缺失、损坏或不匹配不允许未知状态使用零次额度重试。

门户消解涉及两个状态文件，并非跨文件原子事务：若额度已重置而认证状态写入失败，保留认证暂停；该零次记录不会被当作人工重启授权。明确成功后的消解写入失败时，尝试持久写入安全暂停。若消解和安全暂停两处写入同时失败，且进程在存储恢复前退出，重启只能看到先前持久记录，无法恢复本次成功证据；此双重故障和崩溃组合未验证。

存储或审计不可用时应先检查本地安全状态和日志，不能依据操作失败提示推断所有文件均未变化。尤其是门户消解可能先写入额度再写认证状态；人工重置也会先写确认标记再写额度。再次尝试前应重新读取状态，不能手工删除状态文件来获取提交机会。#32 的规则仍适用：未知结果的两次额外提交共用额度、至少间隔 120 秒；重启和外网恢复不重置额度，外网可达时暂停提交并继续只读复检。

补充实现：人工重置的存储故障或损坏记录显示操作未确认及可能部分写入。消解存储故障通过独立状态字段显示，不覆盖最近认证尝试；修订冲突不会被断言为存储故障。该字段只记录服务进程内观测，成功消解后清除，重启后不能据缺省值推断上次故障仍在或已经恢复；直接提交成功后的消解失败另尝试持久安全暂停。若状态快照也无法写入，界面可能只能显示过期或不可确认的状态。提示不改变 #32 的有限重试决策。
