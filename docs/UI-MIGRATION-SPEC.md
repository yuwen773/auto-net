# AutoNet Avalonia UI 迁移与 0.2.1 能力接入规格

Status: ready-for-agent
Tracker: https://github.com/yuwen773/auto-net/issues/1
Date: 2026-10-15（Asia/Shanghai）

## Problem Statement

AutoNet 用户需要在网络异常时迅速知道当前是否在线、应用正在做什么、是否需要自己处理，并能从同一个界面完成诊断、日志查看和安全操作。现有 WinForms 界面已有圆角卡片、语义色和扁平按钮，但其框架与多窗口组织不符合本轮希望采用的现代 Windows 设置式体验；仅重新配色不能满足已确认的框架迁移目标。

0.2.1 后台已经提供通知事件、门户改版信号、浏览器兜底授予和诊断包导出，但现有界面尚未完整消费这些能力。迁移必须保留原有权限、凭据、认证暂停和服务生命周期语义，避免界面升级引入重复开页、错误解锁、凭据泄露或导出覆盖损坏。

## Solution

将全部桌面 UI 迁移至 Avalonia 与官方 Fluent 主题，继续只面向 Windows。采用一个主窗口与左侧导航，提供概览、网络诊断、日志、设置四个页面；默认跟随系统主题，也允许用户手动选择浅色或深色并保存。

概览优先展示当前网络状态、应用处理进度和下一步操作；技术详情按需展开。后台只弹关键通知，同一事件不定时重弹。有效浏览器兜底授予首次立即开页，但跨托盘重启去重并保留十分钟冷却，只打开允许的门户根页面，不填表或携带凭据。用户主动导出诊断包时先选择保存位置，再单独提权采集；覆盖需确认，失败或取消不得破坏已有包或交付半包。

先用最小兼容原型验证托盘、UAC、自包含单文件发布与现有安装契约，再完成全部界面和新能力迁移，提供候选包预览。工程、真实桌面、安装与回退分别验收；真实网络恢复性能不由本轮 UI 验收证明。

## User Stories

1. 作为 Windows 用户，我希望继续使用 Windows 专用的 AutoNet，以便复用现有后台服务和安全机制。
2. 作为已安装 AutoNet 的用户，我希望新界面读取现有服务状态，以便无需重建校园网配置即可查看运行情况。
3. 作为用户，我希望登录 Windows 后托盘按既有方式自动启动，以便日常使用无需手动运行程序。
4. 作为用户，我希望托盘自启时保持隐藏，以便不在每次登录时抢占桌面。
5. 作为升级用户，我希望原有设置和加密凭据继续生效，以便无需为界面升级重新输入密码。
6. 作为用户，我希望关闭主窗口只是隐藏到托盘，以便仍能快速重新打开界面。
7. 作为用户，我希望退出托盘不停止服务，以便后台守护继续运行。
8. 作为用户，我希望同一 Windows 会话只运行一个普通托盘实例，同时仍可启动独立提权操作，以便避免重复界面且不阻塞设置和导出。
9. 作为用户，我希望服务运行不依赖主窗口是否打开，以便界面关闭不影响恢复行为。
10. 作为审阅候选版本的用户，我希望先预览新界面，以便确认体验后再安排覆盖安装。
11. 作为用户，我希望通过左侧导航切换概览、网络诊断、日志和设置，以便在同一窗口完成相关操作。
12. 作为故障中的用户，我希望概览回答当前状态、应用正在做什么和下一步操作，以便快速理解情况。
13. 作为用户，我希望相关操作出现在对应状态附近，以便不必搜索无关页面寻找处理入口。
14. 作为用户，我希望在线与认证暂停分别显示，以便不会把已在线但认证受阻误解成当前断网。
15. 作为用户，我希望缺失、过期、损坏或不可信状态显示为无法确认并禁用相关动作，以便不依据陈旧信息改变恢复状态。
16. 作为快速切换页面的用户，我希望旧异步结果不覆盖当前内容，以便始终看到当前选择对应的信息。
17. 作为用户，我希望轮询、日志读取和导出不冻结界面，以便仍可导航或取消操作。
18. 作为排障用户，我希望查看校园 Wi-Fi、认证、直连、代理或系统路径及 UU 状态，以便区分故障所在层次。
19. 作为排障用户，我希望系统选路推断被明确标注为推断，以便不误认为物理出口已经验证。
20. 作为 UU 用户，我希望进程或连接探测与远程会话实测分开显示，以便不把局部探测当作远程可用证明。
21. 作为用户，我希望门户结构疑似变化与实际认证暂停分别呈现，以便不把所有改版信号误认为已暂停。
22. 作为排障用户，我希望查看受控的阶段与失败分类，以便定位问题而不暴露原始响应或敏感 URL。
23. 作为用户，我希望界面诊断只读且不提交凭据，以便查看问题本身不会触发认证或断网。
24. 作为用户，我希望状态同时使用文字、图标和语义色，以便不只依赖颜色理解异常。
25. 作为中文用户，我希望页面、操作和结果采用一致的中文领域术语，以便区分凭据提交、复检消解与认证暂停。
26. 作为用户，我希望主题默认跟随系统，以便界面与 Windows 外观一致。
27. 作为用户，我希望可手动切换浅色或深色，以便按自己的阅读习惯使用。
28. 作为用户，我希望主题选择跨托盘重启保留，以便无需反复设置。
29. 作为用户，我希望跟随系统时响应系统主题变化，而手动主题不被覆盖，以便选择得到尊重。
30. 作为用户，我希望各页面和应用自有操作窗口的明暗样式一致，以便切换页面不会产生突兀的视觉变化。
31. 作为高 DPI 用户，我希望缩放、窗口调整和长中文内容不会遮挡关键状态或按钮，以便能完成操作。
32. 作为键盘用户，我希望可以按合理顺序导航、看到焦点并触发主要操作，以便不依赖鼠标。
33. 作为用户，我希望关键控件具有与当前可见状态一致的可访问名称，以便辅助工具不会读出旧操作意图。
34. 作为用户，我希望只有需要读取或写入受限设置的操作请求管理员权限，以便普通状态界面保持普通权限。
35. 作为用户，我希望继续选择指定校园网网卡与已保存 Wi-Fi 配置，以便只守护我选定的网络。
36. 作为用户，我希望凭据继续采用 DPAPI 和既有受限存储，以便密码不因框架迁移变成明文文件。
37. 作为已有配置的用户，我希望账号未变且密码留空时可按既有规则保留密码，而换账号时必须提供新密码，以便不会误用旧凭据。
38. 作为用户，我希望取消设置时不改变业务配置，以便查看设置不产生意外写入。
39. 作为用户，我希望保存设置或修改密码不会解除认证暂停，以便安全阻断不被普通编辑操作绕过。
40. 作为用户，我希望恢复开关发送明确的开启或关闭意图，以便状态变化不会把点击解释成相反操作。
41. 作为用户，我希望点击相关动作时再次核对可信状态，以便页面展示后的状态变化不会导致错误操作。
42. 作为用户，我希望解除认证暂停继续要求确认、只读复核、修订核对和审计，以便每次解除都有依据。
43. 作为用户，我希望拒绝 UAC 时不修改设置、认证阻断或服务，以便取消管理员授权没有隐藏副作用。
44. 作为排障用户，我希望继续按已有日期入口查看日志，以便回顾对应时间的事件。
45. 作为用户，我希望日志按既有受限范围显示最新记录并标明范围，以便不把列表尾部误认为完整历史。
46. 作为排障用户，我希望选择日志后查看对应详情，以便关联原因、动作和后续结果。
47. 作为用户，我希望复制日志详情仍保持脱敏，以便可以安全反馈问题。
48. 作为排障用户，我希望继续打开日志目录，以便访问界面列表之外的本地记录。
49. 作为用户，我希望损坏记录被跳过并说明缺口，以便一条坏记录不使日志页失效。
50. 作为快速切换日志的用户，我希望只展示当前选择对应的最新读取结果，以便旧任务不会覆盖新选择。
51. 作为升级用户，我希望兼容既有新旧日志和安全降级显示，以便升级后仍能阅读历史。
52. 作为需要人工处理的用户，我希望收到一次关键通知，以便不必一直盯着主窗口。
53. 作为断网后的用户，我希望观测到联网恢复时提醒一次，以便知道当前外网重新可达。
54. 作为用户，我希望复检开始等过程只在界面显示，以便后台不会逐步弹出通知。
55. 作为重启托盘的用户，我希望当前认证仍暂停时提醒一次，以便仍能知道待处理事项。
56. 作为重启托盘的用户，我希望历史恢复通知不被重播，以便不会误以为刚发生了新的恢复。
57. 作为用户，我希望通知消费记录按 Windows 用户保存，以便托盘重启不造成普通事件反复提醒。
58. 作为长期故障中的用户，我希望同一事件不按固定时间重复弹出，以便避免持续打扰。
59. 作为用户，我希望具体的改版或兜底提示不被同轮通用暂停提示覆盖，以便看到最有用的信息。

64. 作为用户，我希望同一授予跨托盘重启也只自动打开一次，以便重启界面不会重复弹页。

82. 作为项目维护者，我希望先验证框架与集成兼容性，再投入全部迁移，以便尽早发现发布或权限契约缺口。

87. 作为升级用户，我希望覆盖安装保留设置、DPAPI 密文、认证阻断和断线额度并保持 ACL，以便升级不改变安全状态。
88. 作为本机接管人员，我希望保留旧包并能按明确流程回退，以便候选版不适用时可恢复旧界面。

90. 作为项目负责人，我希望真实断网、认证失效、TUN/UU 共存及恢复性能独立验收，以便 UI 成功不会被扩大解释为网络恢复目标已达成。

## Implementation Decisions

1. **框架与平台。** 使用 Avalonia 与官方 Fluent 主题，面向 Windows x64，接续现有稳定 .NET 10 工具链。不是继续打磨 WinForms，也不扩展到 macOS、Linux 或浏览器。
2. **模块职责。** 替换普通桌面展示、托盘及提权操作界面；后台服务继续拥有恢复、认证、复核链、持久阻断和断线额度。Core 的必要改动限于共享呈现契约与已确认的诊断包安全保证，不重写恢复策略。
3. **页面与生命周期。** 单窗口左侧四页；关闭窗口隐藏，退出托盘不停止服务；保留隐藏启动、普通托盘单实例及独立管理员操作的现有入口语义，提权入口不被普通托盘互斥锁拦截。
4. **服务契约。** 继续轮询状态文件，不增加 HTTP 服务、socket 或新守护进程。消费 `Notification(Code, At)`、`PortalLayoutSuspected`、`BrowserFallbackRequested` 和可空 `BrowserFallbackNotBefore`；未知字段兼容，缺少可选新字段时不臆造通知或浏览器授予。
5. **状态可信度。** 沿用状态边界的完整性、时间有效性和安全降级规则。显示时与执行动作前均核验；异步读取有取消、代次和销毁保护，旧结果不能更新新页面。在线、认证状态、门户结构信号和辅助路径证据分别展示。
6. **操作安全。** 恢复开关发送明确 enable/disable 目标；设置、凭据和解除认证暂停继续使用原权限及校验流程。普通编辑或改密码不清阻断，解除必须经用户确认、只读复核、修订核对和审计；界面不自动提交凭据。
7. **主题与偏好。** 跟随系统为默认，可选浅色或深色；手动选择优先于系统变化并跨重启保存。偏好及消费记录按 Windows 用户隔离，不置于受限业务凭据模型中，不降低 private ACL，不保存秘密。
8. **通知范围。** 仅需要人工处理的事件和运行期间观测到联网恢复主动通知。首次读取不重放旧恢复，当前仍暂停时提醒一次；复检过程只展示，不建立定时提醒；按受控代码与单调事件时间消费实际观测，不补造单槽通道中未看到的中间事件。
9. **浏览器首次语义。** ADR-0008 补齐 ADR-0002 的消费端空白：首次有效授予立即开页，不因授予时间加十分钟而延迟首次开页；十分钟用于后续自动开页冷却。不会因此改变服务授予阈值。
10. **浏览器消费。** 按稳定授予时间识别同一授予并持久去重，开页前再次核对可信当前请求。通知消费与开页消费独立；手动开页也计入消费及冷却。服务重启换发授予不能清空本地冷却；同一授予不会因时间到期反复自动打开。状态契约没有故障 ID，不承诺跨服务重启识别同一业务故障。
11. **浏览器边界。** 只在用户会话打开固定允许的门户根地址，不填表或把账号密码放进参数。请求失效、状态不可信或必要消费记录无法安全保存时不自动开页；启动失败给出受控结果和手动入口，不在轮询中无限重试。时间异常不得成为提前重复自动开页的理由。
12. **诊断导出流程。** 用户主动触发，普通 UI 先选择默认当前用户桌面的目标位置并确认覆盖，随后独立 UAC 操作按所选目标采集；拒绝或取消不改目标文件，不能把提权用户的桌面替换成用户已选位置。
13. **诊断包保证。** 复用六类内容、近三天日志和现有脱敏模型；采集仍只读且不加载凭据。既有库直接覆盖和仅采集阶段取消的行为不足以满足规格，必须补齐安全发布、旧包保留和取消保证。提权后的网络缺项或超时仍按既有规则降级，但结果必须披露；取消若已来不及且导出已成功完成，应准确报告成功，不伪报取消或产生半包。
14. **日志兼容。** 保留现有日期、受限列表、详情、复制、目录打开及新旧日志兼容；明确列表范围与缺口。导出读取原有诊断窗口，不能把 UI 最近记录数当作导出范围。
15. **发布契约。** 保留 Tray EXE 身份与启动参数，按自包含 win-x64 单文件和现有安装器复制/回滚契约验证。新增框架依赖必须被候选包接住；不能通过遗漏外置依赖或静默改变安装方式宣称兼容。
16. **迁移顺序。** 兼容原型先过托盘、UAC、主题、单文件及文件布局关卡，然后完成全部 UI 和能力迁移，再生成候选包。暂时保留旧实现用于比较与回退，不把长期两套 UI 维护纳入交付目标。
17. **基线与执行。** 推荐代码基线为 `79ccc029a30b094500d19bb3dec11302aa50b09e`，包含 0.2.1 功能和最终发布记录；使用独立的 `codex/ui-avalonia` 分支，具体工作树由实施任务确认。不要从缺少 B1′–B5 契约的旧 UI HEAD 直接假定已具备新能力，也不要携入仅含过程文件的 checkout checkpoint。
18. **权限与回退。** 候选预览不安装或重启现有服务。覆盖安装前按获授权流程备份；保留设置、密文、阻断、额度、ACL、自启和旧程序。实际安装、回退和破坏性网络测试仍需要分别明确授权；回退验收只能在可本机接管的环境执行。

## Testing Decisions

### 已确认的测试主边界

用户已确认：以候选应用的用户操作及其可观察结果为主要接缝；输入为状态、日志和已有配置，输出为界面、明确操作命令、独立提权助手结果、浏览器启动请求和诊断包。现有 Core/Service 行为回归保留，真实桌面和安装/回退分别验收。

优先复用已有状态/日志重定向夹具、受控时间、模拟门户响应和监测环境。平台副作用用受控适配器捕获，但仍从应用入口驱动；不用仅调用某个私有方法的测试替代界面操作或完整导出，不新增仅为测试服务的 HTTP/IPC 接口。

### 好测试与既有依据

- 断言用户看见的状态、按钮是否可用、传出的明确操作目标、文件最终内容及副作用次数；不锁定私有字段、控件树形状或绘制细节。
- 沿用现有托盘回归中“过期状态不能操作、开关意图明确、UAC 操作独立”的行为；将依赖 WinForms 反射与 GDI 绘制的部分改为适合 Avalonia 的有效测试，不删掉行为要求。
- 沿用现有显示/日志回归中的“在线与暂停分离、损坏记录降级、最近选择获胜、资源释放与重复刷新稳定”场景。
- 接续 0.2.1 的监测、认证持久化、阶段预算、门户信号和诊断包回归。测试使用隔离文件及虚构数据，不能读取或打印真实密码来证明通过。
- 对通知、授予消费和冷却使用可控时间及重启模拟，核验跨进程/重启的记录保留与副作用次数；证明没有重复弹页和非预期认证/断线动作。
- 导出测试验证 ZIP 可读取、六类内容及隐私契约、目标路径、同名覆盖授权、拒绝 UAC、各阶段取消/失败、旧包字节保留和不交付半包。
- 视觉截图用于核对布局、主题与状态矩阵；模拟缩放和离屏渲染只能报告为受控证据，不能冒充真实 Windows DPI、系统托盘或 UAC 交互。

### 完成标准

- 兼容关卡通过后才扩大至全部迁移；若单文件或安装契约不满足，先报告缺口，不能静默改成另一种安装方式。
- 原有及新增行为回归全通过，Release 零警告零错误；候选产物与构建/测试证据对应。
- 明暗主题、键盘、托盘、UAC、导出与实际可用 DPI 环境完成桌面验收；缺少环境的项显式待验收，不能以截图或模拟值补为通过。
- 覆盖安装和旧包回退按单独授权执行，保留数据与权限均核对。仅产出候选包不能标记正式安装或回退已验证。
- 首版正式完成取决于所要求的 UI 发布门槛均通过；真实网络恢复性能另行验收。

## Out of Scope

- 跨平台、Web UI、改用 WinUI 3 或继续以 WinForms 视觉打磨作为主路线。
- 重写后台恢复/认证策略、扩大主动断线能力、改变安全阻断与凭据提交规则、降低 TLS 或 DPAPI/ACL 保护。
- 自动向浏览器填入账号密码、打开任意状态给出的 URL、由服务会话直接弹浏览器。
- 日志中心跨天检索、故障聚合、效果统计、日志保留策略扩大或新增外部分析服务。
- 全面新增高对比主题或承诺尚未验证的全部辅助技术兼容；保留既有可访问语义并验收本轮明确的键盘/焦点/名称要求。
- 真实断网、实际认证失效、提交响应丢失故障注入、TUN/UU 共存、十五秒恢复性能、重启/休眠/长期稳定性验收。
- 未经单独授权的安装、服务重启、代码推送、清除数据或破坏性网络测试。
