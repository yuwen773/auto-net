# 虚拟指针与手动接管：只在内嵌通道页面内做视觉呈现

工单 #40 要求在自动认证时显示虚拟鼠标，让填写与提交过程直观可见，但**不移动、不接管**真实系统鼠标；用户手动操作时暂停新的自动填表与提交，空闲约 15 秒后重新核对再恢复。

## Context

当前自动填表与提交只发生在**独立的内嵌认证通道进程**（`AutoNet.AuthChannel`，ADR-0009）：它用应用自有的 WebView2 隐私会话加载门户页、填表并触发学校页面原有提交。主窗口「上网认证」页按 ADR-0016 只做展示，**不填表、不注入脚本**；ADR-0017 又规定通道会话进行中展示页不保留自己的浏览器。因此主窗口页面既没有真实填表动作，也没有可安全注入覆盖层的脚本入口。

把虚拟指针放到主窗口展示页只能得到两种结果：编造动作（违反“动画只在实际动作发生时播放”），或放宽 ADR-0016/0017 的展示页边界。两者都不可接受。

## Decision

1. **指针画在通道页面内**。通道本来就在自己的 WebView2 页面里注入填表脚本；在同一页面注入一个 `position:fixed`、`pointer-events:none` 的覆盖层，不移动系统鼠标、不拦截真实输入、不触发提交。指针位置来自动作发生瞬间真实控件的 `getBoundingClientRect()`；目标不可用、不在视口或动作失败时隐藏指针，只显示步骤提示。
2. **步骤只来自真实动作**。覆盖层只由通道的四个步骤更新：填写账号、填写密码、勾选协议、提交登录；等待结果单独显示。步骤名与提示是固定受控文案，不包含账号、密码、Cookie 或页面文本。
3. **手动接管在页面内检测**。覆盖层只监听 `isTrusted` 的 `pointerdown`/`keydown`/`input`，向宿主上报“发生过受信任输入”这一事实，不携带按键、坐标或输入值。不监听 `submit` 与 `change`：自动提交的 `click()` 默认动作可能产生受信任的 `submit`/`change` 事件，监听它们会把程序自己的提交误判成人工接管；人工提交与勾选必然先有 `pointerdown` 或 `keydown`。宿主进入接管后：
   - 通道工作流在接管期间返回 `Waiting`，**不预留共享提交额度、不填表、不提交**；
   - 每次新的受信任输入都重新计时；
   - 空闲满 15 秒后仍必须重新核对网络、认证状态、页面来源、表单与共享额度全部成立，才清除接管；
   - 空闲本身从不等于提交授权或认证成功；恢复后仍走原有复核链与额度。
4. **不覆盖用户输入**。填写步骤只写空且未被用户改动的字段；用户改动过的字段（含取消勾选的协议项）一律跳过，并在步骤提示中说明。
5. **尊重减少动画**。读取 Windows“在 Windows 中显示动画”设置，并同时尊重页面 `prefers-reduced-motion`；任一要求减少动画时指针静态呈现、不使用过渡动画。
6. **通道窗口保持屏幕外运行**（用户决定）。指针只在窗口可见时对用户可见；正常自动认证期间窗口仍在屏幕外，只有需要人工或检测到接管时才搬到屏幕内。主窗口认证页继续只投影状态，不声称展示了当时的网页操作。

## Considered Options

- **在主窗口认证页画指针**：需要新 ADR 放宽“展示页不注入脚本”，且展示页没有自动填表动作，指针只能由受控事件驱动；生产中没有真实动作来源。放弃。
- **跨进程把通道的步骤事件投到主窗口**：主窗口仍没有通道的真实页面，坐标无法对应；只能显示文字步骤，不能显示“在页面上”的指针。作为后续增强保留，不在本工单。
- **Avalonia 覆盖层盖在 WebView2 原生表面上**：`NativeControlHost` 承载的是独立 HWND，Avalonia 内容无法可靠绘制在其上方（airspace）；原型也是用页面内覆盖层解决。放弃。
- **用系统鼠标或 CDP 模拟输入**：会移动真实指针或绕过页面自身事件，违反“不移动、不接管真实鼠标”。放弃。

## Consequences

- 凭据与页面边界不变：通道仍然只把凭据写进应用自有的隐私会话；主窗口展示页不获得填表、脚本或提交能力。
- 不新增跨进程契约；步骤、接管与恢复状态全部留在通道进程内，测试用纯策略与脚本字符串断言覆盖。
- 交互检测有明确盲区：跨源框架、浏览器自身界面、脚本被禁用或页面被替换时可能漏检，**不能声称拦截或计数了浏览器中的全部人工提交**。该说明同时写入 `AuthPagePointerPolicy.BlindSpotNote` 与实施记录。
- 正常自动认证期间通道窗口在屏幕外，用户看不到指针；这是“保持现状”的可见性限制，不是指针未实现。真实 WebView2 页面、真实门户、系统多 DPI 与减少动画的现场视觉验证仍为 NOT_RUN。
