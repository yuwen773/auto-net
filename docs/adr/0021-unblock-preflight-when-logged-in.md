# 人工解除的前置复核在门户已登录时不因缺少网关上下文阻断

2026-10-30 现场触发，2026-11-01 补入源码。接续 [ADR-0001](0001-submission-recheck-resolution.md) 与 [ADR-0005](0005-portal-layout-detection.md)，是 2026-10-30 已发布候选包热修（`archive/auto-net-unblock-fix`）的源码化。

## 现场事实

2026-10-30 在本机已安装候选包上执行人工「解除认证暂停」，只读诊断两次都失败：

- 第一次失败是编码问题：Avalonia 宿主没有注册代码页提供程序，门户以 `gbk` 返回状态时 `Encoding.GetEncoding("gbk")` 抛 `ArgumentException`，诊断按结构类失败收尾。这部分已在 `da4594a`（按需注册）修复，并有隔离进程回归覆盖。
- 编码修好后诊断仍失败，但失败分类变成 `MissingGatewayParameters`：门户 `/drcom/chkstatus` 报告 **已登录**，而网关探针没有 302 重定向，于是拿不到 MAC/AC 上下文，`Submission` 阶段以 `MissingGatewayParameters` 收尾。

第二次失败与凭据、密码、额度都无关：网络本身已认证，没有需要提交的凭据，但人工解除被这条前置复核永久挡住。热修在本机装机目录上以 `archive/auto-net-installed-unblock-fix` 标记生效，解除结果为 `Released`，但热修只存在于归档 tag，没有进入任何分支——源码与已安装程序从此分叉。

## 决定

- **人工解除的前置复核在「门户已登录 + 网关不重定向」时不再阻断。** 判据是四个条件同时成立：诊断状态为 `LoggedIn`；失败分类为 `MissingGatewayParameters`；未发出任何凭据请求（`CredentialRequestStarted == false`）；证据显示没有发生重定向（`Evidence.RedirectPresent == false`）。此时网络已认证、没有待提交的凭据，缺少网关上下文不构成解除的安全前提。
- **其余失败一律照旧阻断。** 状态未知、响应结构变化、已登录但重定向里缺登录参数（`RedirectPresent == true` 而上下文不全）等情形继续保留认证暂停——那时缺的是门户登录上下文本身，属于 ADR-0005 的结构类信号。
- **不改变自动认证路径。** 自动认证仍然只在确认 `NeedsLogin` 时提交凭据；门户已登录时没有凭据要发，缺上下文与本决定无关。本决定只放宽人工解除这一个入口的前置复核，不放宽任何提交额度、终态阻断或“终态失败不因在线、保存设置或修改密码解除”的承诺。
- **解除的安全承诺不变。** 仍是确认 → 只读复核 → 修订核对 → 持久审计后解除；审计行先于状态写入落盘；审计失败不得解除。

## 后果

- 已登录且网关不重定向时，人工解除可正常走完四段序列并留下一行审计。
- 人工解除后若会话再次失效，服务仍按既有策略在额度内重试；重试时缺网关上下文会再次以 `MissingGatewayParameters` 收尾并进入既有退避/暂停路径，不会绕过任何终态阻断。
- 判据依赖诊断证据里的重定向存在性，因此 `Evidence` 缺失时按“未知即阻断”处理，不做有利推断。
