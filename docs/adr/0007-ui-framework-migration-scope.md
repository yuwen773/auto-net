# UI 升级优先迁移框架，继续面向 Windows

2026-10-15，用户在 `grill-with-docs` 首轮明确选择 1C / 2A：本次 UI 升级以更换现有 WinForms 框架为优先目标，接受迁移和行为兼容的工作量；产品继续只做 Windows，复用现有后台服务、安全机制和安装方式。继续在 WinForms 上仅打磨外观不作为本轮主路线，跨平台支持不在本轮目标内。

现有 UI 已有圆角卡片、语义状态色和扁平按钮，因此不能把这些已有能力重复计作迁移成果。后续用户明确选择 3A / 4A：采用 Avalonia 与官方 Fluent 主题；首版完整迁移主窗口、设置、日志和托盘，保留既有操作语义，并接通 0.2.1 的通知、诊断包导出和浏览器兜底。日志中心的大规模功能扩展不因本轮选择自动纳入范围。

用户随后明确选择 5A / 6A / 7A：Windows 11 设置式视觉、默认跟随系统且支持手动明暗主题并持久保存、只弹出需要人工处理和联网恢复的关键通知。具体体验约束与待决事项见 [UI 迁移设计记录](../UI-MIGRATION.md)。切换与回退方式及验收门槛尚待后续访谈确定；已确认的设计选择不构成实施或部署授权。

用户进一步选择 8A / 9A / 10A：采用单窗口与左侧导航；同一关键事件只提醒一次，托盘重启仍暂停时提醒一次，不重播历史恢复通知；先以最小原型验证托盘、UAC、单文件发布与安装兼容性，再完整迁移并提供候选包预览，正式替换保留旧版回退。具体首次浏览器兜底时机、发布门槛和实际实施位置仍待确认。

用户已选择 11A / 12A / 13A：浏览器兜底首次立即开页、跨托盘重启去重并计入手动开页；诊断包在普通界面选路径后独立提权，覆盖需确认且失败保留旧包；本轮验收聚焦 UI，不以其替代真实网络恢复验收。此前待定的产品选项已收敛，实际实施基线与工作树提案及阶段验收计划见设计记录，等待最终共享理解确认。

迁移约束包括普通用户托盘与管理员操作的权限分离、DPAPI 凭据及认证暂停的原有安全语义、状态/日志的只读展示，以及退出 UI 不停止后台服务。现有安装器使用固定 Tray EXE 路径及启动参数，并按自包含单文件复制与回滚；候选框架需验证该发布契约，不能直接假定兼容。

本编号接续 `feat/observability-hardening` 分支已存在的 ADR-0001–0006。首版需要消费其服务端通知、诊断包和浏览器兜底契约；UI 文案、去重、首次展示与重复提醒的具体交互仍待确认，不能默认为修改既有服务侧的安全判据。
