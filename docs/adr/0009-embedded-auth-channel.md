# 内嵌认证通道：独立辅助进程承载 WebView2 凭据提交

门户结构改版（`PortalLayoutChanged` 结构信号）会使协议级认证不可用，现有浏览器兜底"只开页不填表"导致守护中断。决定：以应用自有的 WebView2 隐私会话加载真实门户页，自动填写账号密码与协议必选框、触发学校原有提交逻辑——加密与提交仍由学校页面完成。通道只是「凭据提交」的替代载体：复核链、提交结果未知、SubmissionPending、重启不重发等状态机语义一律不变。凭据仅进入本应用隐私会话（不落盘、不进系统浏览器、不进任何第三方进程、会话即弃）；每页最多自动提交一次；验证码与多步登录由人工完成。

形态为**独立辅助进程**（WinForms + WebView2），由托盘按需拉起、结果文件回传，而非嵌入 Avalonia 主窗口。触发采用自动降级 + 设置三态（自动 / 仅手动 / 关闭，落提权编辑器）+ 诊断页手动入口；自动降级复用浏览器兜底的失败阈值与冷却节奏。通道不可用（WebView2 Runtime 缺失、启动失败）时回退系统浏览器兜底。

## Considered Options

- Avalonia `NativeControlHost` 混合嵌入托盘主窗口：UI 统一，但 Avalonia 12 无原生 WebView2 控件、混合宿主无成熟先例，工程风险高——放弃。
- 扩展系统浏览器兜底做自动填表：需向浏览器进程注入凭据，"凭据不进浏览器进程"边界不可守——放弃，保持其原有语义。

## Consequences

- 发布包新增辅助 exe，安装契约在 service/tray 之外新增布局项；`install.ps1`/`uninstall.ps1` 同步扩展。
- 门户改版场景下「复检消解」依赖通道的只读登录结果页判定（此时 chkstatus 只读探针不可用）。
- 受控通知词表需新增通道相关事件码（需要人工、启动失败）。
