# 认证页与内嵌通道的同一会话附着

2026-10-30，实施 [#39](https://github.com/yuwen773/auto-net/issues/39)，接续 [ADR-0009](0009-embedded-auth-channel.md) 与 [ADR-0016](0016-auth-page-display-embedding.md)。本条只决定「上网认证」页在后台内嵌认证通道运行期间**如何呈现**，不改变凭据提交载体。

## 背景

#38 给「上网认证」页接入了真实 WebView2 展示宿主（ADR-0016），ADR-0009 的内嵌认证通道则是独立的提权辅助进程：它用应用自有隐私会话加载门户页、填表并触发学校原有提交。两者都会创建 WebView2 会话并访问同一门户。若同时运行：

- 同一门户同一时刻出现两条浏览器会话、两个一次性用户数据目录；
- 用户可能把展示页误当成“正在提交的会话”，或反过来以为页面在代为提交；
- 展示页的代理与通道的出站路径各自独立，排障时无法判断哪条会话产生了流量。

## 决定

- **会话以通道辅助进程为准**：本进程发起的辅助进程仍存活，或外部启动锁仍被持有（托盘重启后由上一实例启动的通道），即视为“内嵌通道会话进行中”。
- **会话进行中不创建第二个浏览器**：认证页宿主丢弃自己的代理与浏览器，只投影 `ChannelSessionActive`（“内嵌通道会话进行中”），不导航、不填表、不提交。状态核对在每个状态刷新周期执行（`IAuthPageBrowserHost.Refresh`），因此会话开始后最迟一个刷新周期内生效。
- **会话结束只恢复一次只读附着**：宿主回到未附着；协调器仅在本页打开过时重新附着固定门户根地址，从未打开过的页面不会因为一次后台会话凭空拉起代理。恢复不重放任何页面操作，也不提交凭据。
- **协议载体只投影**：后台走协议认证时，页面只显示状态，文案明确“不代表发生过网页操作”，不暗示本页参与过认证。
- **后台节奏不受页面影响**：打开、切页、最小化、关闭页面与通道会话状态都不改变服务的检测周期、退避、共享提交额度或认证暂停。

## 为什么不共享会话

共享会话意味着让展示页接管通道的 cookie 与用户数据目录，或反过来让通道复用展示页的会话。两者都会把 ADR-0009 的“凭据只进入应用自有隐私会话、会话即弃”变成长期会话，并让展示页间接获得凭据提交能力。用“同一时刻只有一条会话”取代“共享一条会话”，既满足用户看到的“正在认证”事实，也不扩大凭据可达范围。

## 边界

- 本决定不声称真实通道进程与真实门户的会话互斥已验证；离线回归用假宿主覆盖两条载体，真实进程与门户仍需现场验收（见 `docs/VALIDATION.md`）。
- 会话进行中丢弃展示页的浏览器会丢失页面上未提交的输入。展示页本来只读、不提交，这一代价被接受，并在受控文案中说明。
- 若将来要让展示页参与填表或提交，必须新开 ADR；不得把本条当成把展示页并入提交载体的许可。
