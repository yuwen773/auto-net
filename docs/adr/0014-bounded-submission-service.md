# 有限重试的协议服务接入与保守计时

2026-10-28，实施 [#32](https://github.com/yuwen773/auto-net/issues/32)，依赖本地已验证但未提交的 #31 持久层。接续 [ADR-0011](0011-bounded-submission-retry.md) 和 [ADR-0013](0013-submission-budget-storage.md)。

## 决定

- `SubmissionRetryPolicy` 是无 I/O 的公开决策边界，输入持久额度、墙钟快照、单调经过时间与外网状态。服务启动或观察到新修订时重新等待完整 120 秒，同时满足持久 `NextPossibleAt`；墙钟前跳不能替代单调等待，回拨或明显偏离单调计时则重新保守等待。结果完成后才观察完成修订，因此预留、复核、发送和结果持久化所用的时间不抵扣下一次等待。
- `IMonitorEnvironment` 增加额度读取、预留、CAS 转换与执行锁边界。普通协议流程先预检，再用新连接检查外网，并重读设置、Wi-Fi、认证状态和额度；持久预留后写入 `SubmissionPending`，最后再次比较认证与额度修订、设置、Wi-Fi、取消和时间证据，任何失败均不授权发送。预检不创建提交额度；预检次数不压掉已发送后可用的共享额度。
- `submission-execution.lock` 用 OS 独占文件句柄贯穿整次协议尝试及结果落盘。复检消解也取得它；仍活动的提交不能被只读观察提前解除。读到中断 `Reserved` 时，只有取得执行锁后才 CAS 为 `PossiblySent`，不退还次数，重新等待完整间隔。执行锁不能替代 #31 的 `auth-state.lock`：后者仍负责额度的读取、预留和修订串行化。
- 未知结果保持 `SubmissionPending`。保留约 2 秒、6 秒的只读复检，之后按 60 秒低频继续，包括额度耗尽和外网恢复时。外网可达只暂停新提交，不清认证状态或额度。明确未登录仍保留间隔；旧 Pending 缺少额度时不经旧冷却分支自动初始化新额度。
- 只有已存在额度且处于 Pending 的受控协议重试，才允许状态端点失联或已知结构但值未知时继续独立网关与配置预检。TLS、状态响应损坏、配置或目标不可信仍拒发；仍须通过持久额度和完整复核链。普通首次提交保持原有状态前置条件。
- 首次提交加两次额外提交后停止，并记录 `SubmissionBudgetExhausted`。明确密码、绑定拒绝或需要人工时立即保存认证终态，再结束额度；独立额度终态写失败不丢掉已保存的明确拒绝。未知响应按可能发送计数；可确认未发出的预留也不退还。
- 明确成功的提交或复检使额度 `Concluded`，保留次数。复检仍经原审计先行、认证修订比较后解除。**本工单不重置额度**；两个审计重置入口归 #34。内嵌载体采用同一记录和执行锁归 #33；当前不声称两条载体已完成共享约束。

## 边界

本次是未提交工作区中的离线实现，不替换已安装服务。#33、#34、#36 升级回滚及真实门户/网络验收仍独立。持久化失败后保留已用次数；无有效证据时停止或延后，不通过初始化、扣次数或缩短等待恢复速度。证据与审查结果见 [#32 实施记录](../progress/32-bounded-submission-service.md)。
