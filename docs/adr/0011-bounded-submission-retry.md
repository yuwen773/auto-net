# 提交结果未知的有限重试：共享提交额度、120 秒间隔、载体无关

ADR-0001 把"已发送但响应丢失"定性为只读复检消解，并承诺"未证实成功前不自动重发"。运行经验显示这条承诺过强：复检保持 Unknown 时（门户无响应、chkstatus 不可用）只能永久停在 SubmissionPending 等人工，而一次 socket 中断就足以造成数小时的守护中断。用户据此选择**有限重试**：结果持续未知时允许再提交，但必须受共享额度、最小间隔和持久预留约束，且不得把"外网恢复"当成认证成功。

本 ADR 修订 ADR-0001 的**重发承诺**，不修订其**复检链**：只读复检仍是 Unknown 的定性路径，仍不发新凭据请求，仍写解除审计。改变的只是 Unknown 之后是否允许再来一次——从"永不"改为"在额度内、间隔满足、前置复核通过时才允许"。

## 决定

- **共享额度**：普通协议提交与内嵌认证通道提交**共用同一个计数**。载体不改变额度，换一条通道不是新的三次。首次提交后，结果持续未知时最多额外提交两次（合计三次）。
- **最小间隔**：相邻两次**可能发出凭据**的提交之间至少 120 秒。这是提交间隔，不是预检间隔；预检可以更频繁。
- **外网恢复不等于成功**：外网可达时暂停提交，继续按受控节奏只读复检。只有门户明确确认登录成功才消解。
- **额度重置条件只有两个**：门户明确确认认证成功（经复检消解链与解除审计）；或用户明确确认"重新开始认证"（先审计、再复核状态）。重启、保存设置、修改密码、外网暂时恢复**都不重置**。
- **提交前持久预留**：在可能发出凭据之前持久记录本次尝试、剩余额度与最早下次提交时刻。持久写入失败、锁竞争未获得或复核发现状态已变时**不提交**。
- **无法区分即按已发送计**：区分"已预留但尚未能证明发送"、"可能已经发送"和"明确结束"。无法可靠区分时按可能发送计入额度并消耗冷却，不能为恢复速度伪造未发送。
- **保守计时**：墙钟回拨、时间不可信、跨重启、持久化失败都必须导致**延后**而不是缩短等待。无法确认上次提交时刻时按最保守解释处理。

## 与既有预检计数的关系

`AuthenticationBlock.Attempts` 当前把预检也计入，`RetryCoolingDown` 是 2–60 秒。这两者**不能**直接解释成 120 秒的提交额度：预检不发出凭据，语义不同，节奏也不同。实施时必须把**预检计数**与**可能发出凭据的提交计数**分开维护，而不是在同一份记录上叠加两个独立的三次上限。

既有自动降级规则在预检尝试用尽时会产生通道授予。授予是**启动意图**，不是提交授权——实际提交仍须走预留与共享额度，不能因为"降级到通道"就多出一次提交。

## Considered Options

- **维持 ADR-0001 的"永不重发"**：安全性最高，但一次丢包就退化为人工处理，与"自动恢复优先"的产品目标冲突。用户已明确选择放弃。
- **不做共享额度，每个载体各自三次**：实现简单，但换载体就能绕过次数限制，门户侧看到的提交总量不可控。放弃。
- **用现有 `AuthenticationBlock.Attempts` 兼作提交额度**：会与预检语义纠缠，且 2–60 秒冷却与 120 秒规则冲突。放弃。

## Consequences

- ADR-0001 的复检链、`SubmissionPending` 状态、"重启不重发"承诺**保持不变**；"未证实成功前不自动重发"改写为"未证实成功前只在共享额度内受控重发"。
- `CONTEXT.md` 的「结果未知的有限重试」条目描述的就是本决定；ADR-0001 应加一行指向本 ADR。
- 需要新的持久记录形态（额度、最早下次提交时刻、预留标记）与跨进程串行化；持久格式调整必须保持旧版本兼容，旧版未知状态、损坏记录、版本未知一律**保守保留阻断**，不能因迁移而凭空获得新额度。升级与回滚需单独测试。
- 回归必须覆盖：0/1/2 次额外提交、120 秒边界、墙钟回拨、并发竞争、写失败拒发、突然退出、跨重启、外网在线暂停、明确失败停止。
- **本 ADR 记录的是决定，不是已交付行为。** 在实现落地并通过离线回归之前，运行中的程序仍遵循 ADR-0001 的"不重发"。
