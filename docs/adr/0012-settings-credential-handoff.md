# 设置凭据交接：独立提权助手与一次性本地管道

2026-10-28，实施 [#30](https://github.com/yuwen773/auto-net/issues/30)，父规格 [#27](https://github.com/yuwen773/auto-net/issues/27)。本决定只覆盖设置草稿交接；主窗口字段合并与输入框清理由依赖本工单的 #41 完成。

## 决定

- 普通进程使用 `SettingsHandoffLauncher.SaveAsync`，以 `runas` 启动自身的 `--save-settings-handoff <关联ID> <发送PID> <进程创建UTC ticks>`。命令行只承载关联元数据，不传设置、账号、密码或文件路径；不添加环境变量，不创建明文交换文件。UAC 等待不阻塞界面线程。
- 提权助手入口先于普通参数解析、QA 参数记录和单实例处理。只允许上述四个参数，不接受混合操作；必须已有提权令牌，不自行再提权。核对发送进程的创建时间、当前 Windows 会话及相同可执行文件路径后才建立管道。
- 提权接收端创建单实例本地命名管道。显式受保护 DACL，只允许接收端 SID 和实际发送端 SID 的 `ReadWrite | Synchronize`，不继承、不授予 Everyone/匿名/管理员组，也不授予 `CreateNewInstance`。客户端按精确权限打开，使用 Identification 级别且句柄不继承。原生创建同时指定 `FIRST_PIPE_INSTANCE`、`OVERLAPPED`、`REJECT_REMOTE_CLIENTS`；对象抢占失败只拒绝，不降级。
- 两端通过管道的内核 PID 查询核对对端，重新读取进程创建时间、主令牌用户 SID、会话、完整映像路径与提权状态，和预期快照逐项匹配。普通发送端预期的是本次启动返回的进程句柄所对应的身份，并要求接收方已提权、同会话且运行同一 EXE。
- 关联 ID 每次新建。发送对象用原子消费标记，接收进程保留已见关联（包括失败与超时），各只允许一次尝试；不重新连接、不重新开放失败的管道。接收端在握手时还生成本实例的新鲜随机挑战，提交确认必须回应该挑战，不能仅回显公开关联 ID。生产助手每个进程只处理一次并退出。另起助手会改变接收 PID/创建时间和挑战，旧发送对象不能接受它，录制的旧确认帧也不能被新助手接受。消费表仅在接收进程内，不是持久化记录；防重放由发送对象消费、预期接收实例绑定、进程内消费表和新鲜挑战共同保证。关联元数据公开可见，其保密性不是安全依据。
- 协议顺序：双方核验 → 关联握手/接收端随机挑战 → 有界完整草稿 → 接收方准备完成 → 发送方用新鲜挑战提交确认 → 接收方再次核验身份并最终检查期限 → 调用既有设置保存 → 仅返回受控结果码。载荷上限 64 KiB，严格 JSON 契约拒绝缺字段、空引用、未知/重复字段与过深内容；传输字节缓冲在 finally 中清零。
- 普通端的 30 秒单调期限从建立本次交接对象时起算，包括启动/UAC 等待；接收端另有 30 秒本地期限。用户若在 UAC 停留过久，即使最终同意也不会交出载荷。UAC 系统对话框本身无法由本协议强制取消；取消后启动返回的助手只会等待超时并退出。

## 零写入与结果未知的边界

身份不符、重放、载荷损坏、用户取消及**提交确认前**的交接超时，均在调用保存之前终止，零写入。接收方收到完整确认并在其期限内完成最后复核，才进入保存。

提交确认可能已发出后，如果回执超时、连接中断或保存适配器抛异常，普通端返回 `OutcomeUnknown`，不自动重试。这个场景不能证明零写入：接收端可能已保存，或者按既有顺序只写了凭据。确认后的回执交付与磁盘保存无法构成一个原子事务。这里是对 #30 “超时零写入”的明确工程边界，不能将其宣称为任何时刻超时都可回滚。

完整回执中的 `SettingsSaveOutcome` 复用既有凭据规则与校验。`StoreFailed` 仍表示保存未完成，不能理解为回滚成功。交接代码不读取/修改认证暂停、共享提交额度或网络配置；实际写入只发生在既有 `ElevatedSettings.Save` 的适配器内。

## 验证范围

同账户两个独立进程、真实管道 ACL、身份不符、确认前多阶段超时、过期关联、重放、损坏消息、UAC 拒绝的启动适配器、回执丢失与隔离 DPAPI 保存由回归覆盖。没有运行真实 UAC 成功交接；跨管理员账户 UAC 本机未构造，记为 `NOT_RUN`。代码允许接收 SID 与发送 SID 不同，但这不是跨账户成功证据。

同用户进程注入、可执行文件替换/签名信任、完整性级别间的实际令牌读取、远程/跨会话攻击实测和系统休眠期间的期限行为未验证。路径相同与 SID/PID 核验不证明可抵御已控制合法进程的攻击。真实校园网、安装/升级/回滚没有执行。

权限依据：[微软命名管道安全与访问权限](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights)、[CreateNamedPipeW](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-createnamedpipew)。
