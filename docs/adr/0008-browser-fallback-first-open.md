# 浏览器兜底首次立即开页，冷却约束后续自动开页

0.2.1 服务在授予浏览器兜底时立即置标志，同时将 `BrowserFallbackNotBefore` 写为授予时刻加 10 分钟；此前代码、ADR 和测试没有明确首次打开是否等待。2026-10-15，用户在 UI 迁移访谈 Q11 明确选择 A：首次立即打开一次，10 分钟用于再次自动开页的冷却，同一请求跨托盘重启不重开，手动开页也计入去重。

这一决定补齐消费端语义，不改变服务端失败阈值、认证阻断或凭据规则。服务授予不等于认证成功，也不等于浏览器已打开；通知消费与浏览器消费分开记录。仅在重读可信当前状态、确认请求仍有效后，在普通用户会话打开固定允许的门户根地址，不填表或携带凭据。

UI 持久保存授予消费记录及最近开页冷却。单次授予只自动打开一次，冷却时间到期本身不触发重开；服务重启换发授予也不能绕过本地冷却。仅新的有效授予且冷却已满足时可再次自动打开，持续请求可由用户手动处理；启动失败显示错误和手动入口，不在轮询中无限重试。status.json 没有故障 ID，不能宣称能识别跨服务重启的同一业务故障，实际保证是按授予去重与跨授予冷却。
