# 提交结果未知后只读复检消解，而非直接重试或永久人工

10-13 16:34 一次 socket 中断（995）让凭据请求发出后响应丢失，按当时设计进入 SubmissionPending 永久暂停，人工解锁约 3 小时。cmcc-autoconnect 的经验是门户经常收下请求不回响应，所以提交超时不判失败、先复检联网状态。我们决定把“已发送但响应丢失”的定性从“只能人工”改为“只读复检定性”：复检不发任何新凭据请求，“重启不重发凭据”的承诺因此保持不变，改变的只是未知结果的解释路径。

## 判据

复检只读 chkstatus（InspectAsync，独立预算，提交未知后约 2s、6s 各一次）：

| 复检结果 | 定性 |
|---|---|
| LoggedIn | 消解为 Accepted：修订比较清阻断、尝试计数重置、写 SubmissionResolved 事件并追加解除审计（Action=复检消解） |
| NeedsLogin | 明确未成功：LoginRejected，进入 RetryCoolingDown 冷却重试（今天此路直接永久暂停；能观察到“未登录”是新信息，不构成回归） |
| Unknown（探测失败） | 无法定性：保持 SubmissionPending 人工处理，不放松 |

外网探测结果只作证据记录，不作为消解依据；chkstatus 是认证侧唯一权威。

## Consequences

- 安全承诺文案从“模糊结果永不重试”改写为“模糊结果经只读复检定性，未证实成功前不自动重试”（README 同步）。
- 复检消解除外与人工解除同路径写审计，保证每一次阻断消失都可追溯。
- QA 故障注入（环境变量模拟提交后响应丢失）用于离线回归与实机诱发验证。
