- UU 远程已安装，`GameViewerService` 为自动启动的 LocalSystem 服务，进程位于 Session 0。仍不能据此断言未登录时远程连接一定成功。

- 与校园网有关的本机浏览器跳转记录提供了 `login.csust.edu.cn` 线索；随后已直接核实该站点公开页面和脚本。
- `/drcom/chkstatus` 当前返回已认证；没有提交账号密码，没有主动登出、断网或重置网卡。
- 页面配置确认 `en_md5=0`、`password_cut=0`、`enable_r3=0`；当前 PC 页面无运营商选择控件，隐藏字段 R1/R3/R6=0、para=00。
- 公开 JS 使用 `/drcom/login`、HTTPS、JSONP、DDDDD/upass/0MKKey 等参数，未在该登录请求中发送验证码字段。
- 使用应用实际网络代码只读诊断：Wi-Fi 已连接、有 IPv4、直连 HTTPS 内容检查通过、Dr.COM 已认证、系统检测选路经过 TUN 且可达。
- UU 服务运行；当前无法从 TCP 连接观察确认其在线状态。UU 可能使用其他传输方式，不能据此判定其掉线。

## 自动检查

`scripts/build.ps1` 执行编译和测试程序。覆盖：

- 正常在线、断连、认证失效、上游异常、暂停、缺少凭据。
- 前 15 秒快速尝试、重试退避、恢复后清零、明确凭据拒绝后停止认证。
- JSONP 严格解析、查询参数编码、匹配真实协议的 HTTP 夹具、已经认证时不提交、模式变化时停止。
- 重定向和假登录页不视为外网成功。
- DNS 压缩答案、错误事务 ID、逐字节截断响应。
- 不安全认证地址、远程代理和带令牌检测 URL 的拒绝。

HTTP 夹具和模拟策略测试不等于真实校园网认证成功。没有真实凭据和故障观测时，不能报告 15 秒目标已通过。

## 安装后必须验收

在本机有人可操作、无需依赖当前远程会话的时段进行：

1. 安装服务并保存真实凭据，检查后台状态、目录 ACL、托盘自启和服务恢复设置。
2. 正常联网运行至少 10 分钟：不应反复认证或切断 Wi-Fi；直连和 TUN/系统路径应分别显示。
3. 一次受控 Wi-Fi 断连：从实际断开时刻计时到 HTTPS 外网探测恢复，记录总耗时；目标 ≤15 秒。
4. 认证失效：在允许的测试时段使认证失效，验证实际 Dr.COM 登录成功以及外网恢复；目标 ≤15 秒。
5. 用 HTTP 夹具检查错误凭据；如需真实校验，仅做一次可控验证，确认明确拒绝后不会循环提交。
6. 在允许的测试时段制造代理故障：校园网在线时，应报告代理/系统路径异常，且不重置校园 Wi-Fi、不重启 UU/Mihomo。
7. 重启电脑，停留在 Windows 登录界面：从另一台设备通过 UU 建立连接，验证开机认证和远程可用性。
8. 接通电源时检查系统唤醒申请；暂停/停止服务后申请释放。睡眠唤醒后检查恢复检测。

若真实端到端超过 15 秒，需要从 Wi-Fi 关联、地址获取、DNS、认证和 UU 自身重连分别定位耗时。不能只缩短轮询间隔就宣布达标。
