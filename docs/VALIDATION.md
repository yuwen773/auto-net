2. 正常联网运行至少 10 分钟：不应反复认证或切断 Wi-Fi；直连和 TUN/系统路径应分别显示。

4. 认证失效：在允许的测试时段使认证失效，验证实际 Dr.COM 登录成功以及外网恢复；目标 ≤15 秒。
5. 用 HTTP 夹具检查错误凭据；如需真实校验，仅做一次可控验证，确认明确拒绝后不会循环提交。
6. 在允许的测试时段制造代理故障：校园网在线时，应报告代理/系统路径异常，且不重置校园 Wi-Fi、不重启 UU/Mihomo。
7. 重启电脑，停留在 Windows 登录界面：从另一台设备通过 UU 建立连接，验证开机认证和远程可用性。
8. 接通电源时检查系统唤醒申请；暂停/停止服务后申请释放。睡眠唤醒后检查恢复检测。

若真实端到端超过 15 秒，需要从 Wi-Fi 关联、地址获取、DNS、认证和 UU 自身重连分别定位耗时。不能只缩短轮询间隔就宣布达标。

## 交付状态与证据口径

工程计划见 [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)。工程回归通过、实机功能通过、性能与稳定性通过是三个独立门槛。真实用例无法执行时标记“待验收/受阻”，不得据此标记产品目标完成。

| 证据 | 能说明什么 | 不能说明什么 |
|---|---|---|
| HTTP/策略夹具 | 给定输入下的守卫和动作正确 | 学校实际接受凭据、真实恢复耗时 |
| Wi-Fi socket 绑定 | 程序请求使用指定接口和源地址 | 请求一定未被 TUN/WFP 接管 |
| Windows 路由查询 | 某目标的系统选路推断 | 实际 HTTP 连接或物理出口 |
| 物理网卡脱敏抓包 | 指定时段和目标的实际出口 | 所有请求永远绕过隧道 |
| UU 进程/TCP/服务探测 | 相应局部状态 | 第二设备成功建立远程会话 |

抓包只保留探测目标与必要的接口/时间证据；不要抓取或保存带凭据的认证 URL、完整数据包载荷、账号、Cookie、MAC、SSID 密码或 Token。发布、提交和上传前人工审阅脱敏结果。只读诊断会发出探测流量，但不能连接/断开 Wi-Fi、调用登录、加载密码或修改路由。
